Two ways to build a parser from a CFG

Everything below works from the same idea: a context-free grammar doesn't tell you, by itself, which production to apply next. Both parser families solve that by pre-computing static properties of the grammar (Nullable, FIRST, FOLLOW, and for SLR, LR(0) items) and baking the result into a table. Where they differ is how they read the input and what the table is indexed by. This site walks both pipelines step by step, in the same style, using the same running example grammar, so the two can be compared directly.

Running example throughout: Grammar 2.9 — T → R, T → aTc, R → ε, R → bR. It's small enough to hand-compute fully, and the textbook uses it for both the LL(1) table and the SLR table, which makes it the cleanest way to see the two constructions diverge from identical raw material.
