Homework 3 · Bottom-Up Parsing

Constructing the SLR table, then running it

Given the homework grammar, construct every LR(0) item set using CLOSURE and GOTO, read the control DFA, fill the SLR ACTION/GOTO table, and use that finished table to parse ((n+n)*n).

Part 1 — Start with the augmented grammar and its fixed sets

0. T′ → T (augmentation) 1. T → n 2. T → ( T + T ) 3. T → ( T * T ) Nullable(T)=false FIRST(T)={(, n} FOLLOW(T)={+, *, ), $}

The grammar is not LL(1): rules 2 and 3 both begin with (, so their FIRST sets overlap. SLR postpones that choice until enough of the right-hand side has been recognised.

The FOLLOW set is used only for reductions. A completed T item may reduce only when the next input token is +, *, ), or $.

CLOSURE(I) If an item is A→α•Nβ and N is a nonterminal, add N→•γ for every N→γ. Repeat until no item can be added. GOTO(I,X) Advance • across X in every item with X immediately after the dot, then apply CLOSURE. The raw dot-advanced items alone are not a finished state.

Part 3 — Read the control DFA from the item-set GOTO edges

Each item set becomes one DFA state; each GOTO calculation becomes a labelled edge. Terminal edges become shifts and the nonterminal edges become parser GOTO entries.

Part 4 — Fill the parsing table from the control DFA

The DFA tells us the next state after a recognised grammar symbol. A terminal edge is a future shift; a nonterminal edge is a future parser goto. Completed items add reductions using FOLLOW.

Reading the stackThe stack interleaves grammar symbols and DFA states, with the current state on top. Reducing T→β pops one symbol/state pair for every symbol in β, exposes a state, then pushes T and GOTO[state,T]. A reduction never consumes input.

Part 6 — Homework 3(b): make an LL(1) grammar for the same language

The original grammar is not LL(1) because the two parenthesised rules begin with the same terminal (. We do not need to change the language; we only need to delay the choice between + and * until after the first subexpression has been read.

The new grammar G′ — exactly four productions 1. T → n 2. T → ( T O T ) 3. O → + 4. O → *

Step 1: where G′ comes from

Original pair: T → ( T + T ) T → ( T * T ) Common prefix: ( T Different choice: + or * Common suffix: T ) Factor the choice into a new nonterminal O: T → ( T O T ) O → + | *

Choosing O→+ recreates T→(T+T); choosing O→* recreates T→(T*T). Together with T→n, G′ therefore generates exactly the same strings as G.

Step 2: prove that G′ is LL(1)

ConclusionEvery nonterminal in G′ has alternatives with non-overlapping FIRST sets, and there are no ε-productions requiring a FOLLOW-set exception. The predictive parser can therefore select one production from one lookahead token: G′ is LL(1).

What this shows

  • LL(1) fails at the opening parenthesis in G because both compound productions have the same initial terminal.
  • The SLR DFA keeps both possibilities alive in I3 and distinguishes them only in I4, after the left T is complete and the operator is visible.
  • Part 6 shows the LL(1) alternative: left-factor that same shared prefix and let O choose the operator.
