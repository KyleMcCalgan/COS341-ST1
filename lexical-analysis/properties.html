§1.9 · Theory

Properties of Regular Languages

The most "exam question" section in this chapter, and the easiest to under-prepare for because none of it is a step-by-step algorithm — it's a set of facts and proof techniques about what regular languages can and can't express.

Relative expressive power (§1.9.1)

Regexes, NFAs, and DFAs all describe exactly the same class of languages — the regular languages. What differs between them is description size, not expressive reach:

  • Regex → NFA: linear size increase (each subexpression contributes a bounded number of new states/transitions).
  • NFA → DFA: potentially exponential — up to 2ⁿ−1 states from an n-state NFA.
  • NFA/DFA → regex (the reverse direction): can also be exponentially larger — mostly of academic interest, since this direction is rarely needed in practice.
The exponential-blowup proof construction (Fig. 1.14) For each n, build an n-state NFA: - state 0 is the start state, state n-1 is accepting - state i has a transition to state i+1 on symbol a (for i < n-1) - EVERY state has a transition to itself AND to state 0 on symbol b Represent a set of these states as an n-bit number (bit i = 1 iff state i is in the set). - a transition on a doubles the number (shifts left), mod 2^n - a transition on b sets bit 0 (bitwise OR with 1) Starting from the number 1 (just the start state), these two operations can reach every possible n-bit number — so the subset construction produces a DFA state for every one of the 2^n - 1 non-empty subsets. And they're all DISTINGUISHABLE: a subset containing NFA state i accepts on exactly n-1-i more a's, so any two different subsets can be told apart by some string — meaning the resulting DFA is not just big, but minimal.

Why this matters as a technique: it's not enough to exhibit one bad case — a real blowup proof needs an infinite family of NFAs with the blowup provably present at every size, and needs to argue the resulting DFA is minimal (otherwise the "blowup" might just be sloppy, avoidable construction).

Limits to expressive power (§1.9.2)

A DFA is finite — it has nowhere to store an unbounded count. That single fact rules out a whole class of languages:

Classic non-regular example L = { aⁿbⁿ | n ≥ 0 } (any number of a's, followed by EXACTLY that many b's) Not regular: reading left to right, by the time all the a's are read, a finite automaton would need to have "remembered" exactly how many there were, in order to check the b's against that count — but a finite number of states can only distinguish finitely many different counts, not aⁿ for unboundedly large n.

Contrast this with bounded-depth parenthesis matching — matching parens up to some fixed maximum nesting depth n IS regular, recognisable by a DFA with exactly n+1 states (state i = "i unmatched opens so far"). The moment nesting is unbounded, it's no longer regular for the same reason as aⁿbⁿ.

On the flip side, some very complex-looking languages ARE regular — e.g. the set of all syntactically valid programs under a billion characters long is technically a (finite, hence regular) language, even though describing it as a regex would be absurdly impractical. Regularity is about a structural limit, not about "looking simple."

Closure properties (§1.9.3)

Given regular languages, what operations on them are guaranteed to produce another regular language?

OperationWhy it's closed
UnionDirect — s|t is a regex for L(s) ∪ L(t)
ConcatenationDirect — st
Unbounded repetition (star)Direct — s*
ComplementBuild a DFA for L with a total transition function (§1.7.2 style), then flip every accepting state to non-accepting and vice versa
IntersectionVia De Morgan's: L1 ∩ L2 = complement(complement(L1) ∪ complement(L2))
Set differenceL1 \ L2 = L1 ∩ complement(L2)
Prefix, suffix, subsequence, reversalEach obtainable by a direct transformation of the DFA (details vary per operation)

Practical task these set up: given closure properties, argue formally that a derived language is (or isn't) regular — or, given automata for L1 and L2, actually construct the automaton for their complement/intersection/difference rather than re-deriving a language description from scratch.
