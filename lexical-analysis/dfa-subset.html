NFA → DFA

Deterministic Finite Automata & the Subset Construction

A DFA is an NFA with the nondeterminism surgically removed: no ε-transitions, and never two identically-labelled transitions out of the same state. That determinism is exactly what makes it cheap to run — table lookup, one step per input character, no backtracking.

Want to build this table yourself, one state at a time? The interactive walkthrough steps through the exact work-list algorithm below on this page's worked example.

DFA fundamentals

Two restrictions turn an NFA into a DFA:

  • No ε-transitions.
  • No two transitions out of the same state carry the same label.

This means the transition relation is a genuine (partial) function δ(state, symbol) → state. Implementation is direct: a 2D table cross-indexed by state and symbol gives the next state (or "no transition" = error), and a 1D table marks which states are accepting.

ε-closure — the piece that makes conversion possible

Definition 1.2 ε-closure(M) = the smallest set X such that: M ⊆ X, and if s ∈ X and there's a transition s -ε-> t, then t ∈ X i.e.: start with M, and keep adding anything reachable by ε-transitions alone, until nothing new gets added.

This is a genuine fixed-point computation — same style as Nullable/FIRST/FOLLOW on the parsing side, just over sets of NFA states instead of grammar properties. It's solved the same way: start from the seed set, repeatedly apply the "add anything one ε-step away" rule, stop when nothing changes.

The Subset Construction (Algorithm 1.3)

The core idea: simulate every possible NFA path at once by tracking the whole set of NFA states you could currently be in. Each distinct reachable set becomes one DFA state.

Algorithm 1.3, as a work-list procedure s0' := ε-closure({n0}) n0 = the NFA's start state S' := { s0' } (unmarked) while there is an unmarked state s' in S': mark s' for each symbol c in the alphabet: T := { t | s ∈ s' and s --c--> t is an NFA transition } target := ε-closure(T) if target is nonempty: if target ∉ S': add target to S' (unmarked) record move(s', c) = target A DFA state s' is accepting iff s' contains at least one accepting NFA state.

This is the exact same "unmarked work-list" pattern used to solve ε-closure itself, and the same pattern used for the LL(1) table's FIRST/FOLLOW fixed points — pick an unmarked item, process it, mark it, repeat until nothing unmarked remains.

Size vs. Speed (§1.6)

Runtime≈ O(c·|N|·|v|) — c a constant, |N| automaton size, |v| input lengthO(k·|v|) — k independent of automaton size
SizeLinear in the regexUp to 2ⁿ−1 states from an n-state NFA in the worst case

In practice, DFAs built from real programming-language token regexes rarely blow up anywhere near that worst case — which is why nearly all production lexers are DFA-based despite the theoretical risk.
