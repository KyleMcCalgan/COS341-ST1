Minimization

DFA Minimization

The subset construction can leave behind redundant states — different sets of NFA states that nonetheless behave identically from here on. Minimization finds and collapses these, and (remarkably) every regular language has one unique minimal DFA, which makes minimized DFAs a clean way to test whether two descriptions denote the same language.

Want to split the groups yourself, one inconsistency at a time? The interactive walkthrough runs the exact partition-refinement algorithm below on this page's worked example.

When are two states equivalent?

Not just "do their immediate transitions look the same" — two states can be equivalent even if their transitions go to different-looking states, as long as those target states are themselves equivalent. So minimization works by assuming everything is equivalent, then proving states apart only when it can:

  • An accepting state is never equivalent to a non-accepting one.
  • If states p and q both have a transition on symbol c, but those transitions lead to states already proven different, then p and q are different too — and this also applies if only one of p, q even has a defined transition on c.

Algorithm 1.4 — partition refinement

Algorithm 1.4 1. Start with two groups: F (all accepting states) and S\F (all non-accepting states). Both unmarked. 2. Pick any unmarked group G. Check consistency: for every pair of states in G, and every symbol c, do their c-transitions land in the same group (or are both undefined)? - If G is consistent: mark it. - If not: split G into maximal consistent subgroups, replace G with them, and unmark every group again (a split can invalidate an earlier "consistent" verdict). 3. Repeat step 2 until no unmarked group remains. The final groups are the states of the minimal DFA. Optimisation: a singleton group can never need splitting further, so skip it in step 2 — stop once every unmarked group is a singleton.

The starting state of the minimal DFA is whichever group contains the original start state; any group made entirely of accepting states is accepting in the minimal DFA.

Worked in full: minimizing the (a|b)*ac DFA

Picking up the 4-state DFA from the subset construction page:

s2's1's2'—
s3'———
Step 1 — initial split F = {s3'} (accepting) S\F = {s0', s1', s2'} (non-accepting)
Step 2 — check {s3'} Singleton — automatically consistent. Mark it.
Step 3 — check {s0', s1', s2'} Transition table for this group: a b c s0' s1' s2' — s1' s1' s2' s3' s2' s1' s2' — On c: s0' and s2' both have NO transition (consistent with each other), but s1' transitions to s3' — which is in a DIFFERENT group. So this group is INCONSISTENT. Split into maximal consistent subgroups: {s0', s2'} — both: a→s1', b→s2', c→undefined (identical pattern) {s1'} — the odd one out, because of its c-transition Result: three groups now — {s3'}, {s0', s2'}, {s1'}. Unmark everything (including {s3'}).
Steps 4–5 — re-check everything {s3'}: singleton, consistent, mark. {s1'}: singleton, consistent, mark. {s0', s2'}: both states have IDENTICAL transitions (a→s1'-group, b→{s0',s2'}-group itself, c→undefined) — consistent. Mark. No unmarked non-singleton groups remain. Done.

Result: 3 groups → 3-state minimal DFA, exactly matching what the textbook notes by inspection: s0' and s2' "are equivalent: neither are accepting and they have identical transitions."

Dead states — the trap (§1.7.2)

Algorithm 1.4 quietly assumes either every state has a transition on every symbol, or there are no dead states (states from which no accepting state is reachable at all). If both assumptions fail, the algorithm can under-minimize.

Why: a transition to a dead state and an undefined transition both mean "this path can never accept" — they should be treated identically. But the consistency check in step 2 treats them differently (one is a transition to a specific state, the other is "no transition" at all), so it can split a group that didn't actually need splitting.

Two fixes (1) Remove dead states first, via a simple reachability analysis (any state that can't reach an accepting state gets deleted, along with transitions into it). This is always safe for DFAs built from regular expressions by the standard construction, since that process never introduces dead states in the first place.

(2) Do the opposite — make the transition function total by adding one explicit dead state that every undefined transition now points to (and which loops to itself on every symbol). Minimize normally, then remove the group containing that dead state from the result.

Why this matters beyond just "smaller automaton"

Every regular language has exactly one minimal DFA (up to renaming states) — which gives a clean equivalence test: to check whether two regexes, NFAs, or DFAs describe the same language, minimize both and compare the results directly.
